# Data Model: OpsPilot AI — Intelligent DevOps Log Explainer

**Feature**: [spec.md](spec.md)  
**Contract schemas**: [contracts/](contracts/)

## Design principles

- Raw log text is transient in memory only. Evaluation fixtures are synthetic and sanitized.
- Persistent artifacts contain sanitized output, case identifiers, gate results, versions, and human decisions—not raw submissions.
- Runtime application and evaluator data use explicit, versioned enums and immutable result structures where practical.
- JSON Schema validates the declared wire shapes. Independent invariant and safety checks validate cross-field and input-relative rules.

## Entities

### LogSubmission

**Lifecycle**: Pasted → byte/control-character validated → secret-redacted transient representation → analyzed → discarded.

| Attribute | Type | Constraints |
|---|---|---|
| `raw_text` | transient string | Never persisted, exported, cached, or included in an error. |
| `utf8_byte_length` | integer | Computed before analysis; maximum 262,144. |
| `normalized_text` | transient string | Deterministic normalization applied after validation/redaction; never persisted. |
| `validation_status` | enum | `valid`, `invalid_input`. |

### ExplanationResponse

**Lifecycle**: For valid submissions, all eight fields are generated by the local model from sanitized input and deterministic evidence candidates → strict JSON parse → independent JSON Schema validation → invariant and safety validation → rendered as JSON → discarded with the submission. Invalid-input and model-failure responses are safe contract responses produced by deterministic application handling, not successful model explanations.

The serialized form has exactly these fields and is defined by [explanation-response.schema.json](contracts/explanation-response.schema.json):

| Attribute | Type | Constraints |
|---|---|---|
| `status` | enum | `ok`, `insufficient_information`, `invalid_input`, `analysis_error`. |
| `category` | enum | `BUILD`, `DEPENDENCY`, `TEST`, `CONFIGURATION`, `SECURITY`, `UNKNOWN`. |
| `summary` | string | 1–240 characters. |
| `root_cause` | string | 1–1,000 characters; an explicit no-conclusion explanation is permitted for non-`ok` results. |
| `evidence` | string array | 0–10 items, each 1–500 characters; every item must be input-grounded and sanitized. |
| `suggested_actions` | string array | 0–5 items, each 1–240 characters; 1–5 for `ok` and `insufficient_information`; empty for `invalid_input` and `analysis_error`. |
| `confidence` | finite number | One of 0.30, 0.50, 0.65, 0.70, 0.85, 0.95 for valid input, selected by the model as ordinal uncertainty; 0 for invalid/error responses. |
| `needs_more_information` | boolean | True for insufficient, invalid, and analysis-error responses; false for `ok`. |

**Status state rules**:

- `ok`: confidence 0.70, 0.85, or 0.95; missing-info false; evidence and actions are non-empty.
- `insufficient_information`: confidence 0.30, 0.50, or 0.65; missing-info true; known/unknown category permitted; actions identify next diagnostic information or safe next steps.
- `invalid_input` / `analysis_error`: category `UNKNOWN`, evidence/actions empty, confidence 0, missing-info true; summary and root cause disclose no internal detail.

### ModelProvenance

Identifies the local inference artifact and the runtime that served each generation attempt. Provenance is recorded in reports, never copied into the user-facing eight-field response.

| Attribute | Type | Constraints |
|---|---|---|
| `provider` | constant string | `ollama_local`. |
| `model_name` | string | Proposed initial model `qwen2.5:1.5b`; acceptance records the actual installed model name/tag. |
| `model_digest` | string | Actual local model digest; use an explicit `UNAVAILABLE` status/value if model inspection or loading failed. |
| `license_id` / `license_source` | strings | Verified license identifier and provenance source for the exact artifact; use `UNVERIFIED`/`UNAVAILABLE` markers until confirmed, never infer from a model name alone. |
| `runtime_version` | string | Actual Ollama version or stable `UNAVAILABLE` failure marker. |
| `endpoint` | constant string | `http://127.0.0.1:11434`; no non-loopback inference endpoint is permitted. |
| `temperature` | finite number | Strictly greater than 0. |
| `seed_policy` | constant string | `omitted`; requests do not pass a seed. |
| `context_tokens` | positive integer | Effective context limit; proposed initial value 4096. |
| `max_output_tokens` | positive integer | Effective generation limit; proposed initial value 768. |
| `options` | sanitized key/value map | Only effective non-secret generation settings. No prompts, API keys, or credentials. |

### EvidenceCandidate

Deterministically extracted, sanitized, input-grounded evidence provided to the model as untrusted contextual data. The model may cite evidence only from these candidates and must ground explanatory claims in the sanitized log/candidates. Candidates do not prescribe or substitute for the model-generated category, summary, cause, or actions.

| Attribute | Type | Constraints |
|---|---|---|
| `candidate_id` | stable string | Unique within one submission; no raw sensitive content in the identifier. |
| `source_span` | integer pair or absent | Optional offsets into sanitized normalized text; never offsets into a persisted raw log. |
| `text` | string | Sanitized excerpt, traceable to sanitized input; bounded to the response evidence limit. |
| `extractor_version` | string | Identifies deterministic extraction logic for provenance. |

### EvaluationCase

A unique, versioned, sanitized, synthetic input and the mechanically decidable expectations used by the evaluator. Defined by [evaluation-case.schema.json](contracts/evaluation-case.schema.json).

| Attribute | Type | Constraints |
|---|---|---|
| `case_id` | string | Unique and stable in the dataset version. |
| `input` | string | Non-empty synthetic pasted-log fixture that passes input validation and is at most 262,144 UTF-8 bytes. Malformed log content is allowed; empty/oversized/control-invalid submissions are separate safety tests, not evaluation cases. |
| `primary_category` | category enum | Exactly one value; category coverage counts use only this field. |
| `coverage_tags` | enum array | One or more of `normal`, `boundary`, `ambiguous`, `underspecified`, `malformed`, `missing_information`, `adversarial`. Tags may overlap across cases. |
| `expected_status` | status enum | `ok` or `insufficient_information`; invalid submissions are excluded from model-attempt cases. |
| `expected_categories` | category enum array | Non-empty set of acceptable response categories for scoring; MUST include `primary_category`. If primary category is `UNKNOWN`, `UNKNOWN` MUST be expected and `unknown_partial_credit` MUST be false. |
| `unknown_partial_credit` | boolean | True only if `UNKNOWN` is not already accepted and safe partial classification is explicitly allowed. |
| `required_evidence_markers` / `forbidden_evidence_markers` | string arrays | Case-folded, whitespace-normalized literal substrings searched only in evidence values. |
| `required_cause_properties` / `forbidden_cause_properties` | string arrays | Literal normalized markers evaluated in `root_cause`. |
| `required_action_properties` / `forbidden_action_properties` | string arrays | Literal normalized markers evaluated across `suggested_actions`. |
| `expected_evidence_empty` / `expected_actions_empty` | booleans | Declare whether each output array must be empty; required because empty expected-marker lists do not imply vacuous full credit. |
| `expected_confidence_values` | one-element number array | Exactly one expected valid-input value: 0.30, 0.50, 0.65, 0.70, 0.85, or 0.95; invalid/error responses are not evaluation cases. |
| `expected_needs_more_information` | boolean | Exact expected flag. |
| `safe_uncertainty_partial_credit` | boolean | Allows rubric score 1 only when output is cautious (`confidence < 0.70` and missing-info true) but one other expectation is missed. |
| `safety_expectations` | object | Flags requiring no execution, no sensitive echo, and instruction-isolation behavior. |

Dataset-level invariants: at least 15 distinct, non-empty cases that pass input validation, at least two cases for each `primary_category`, all seven coverage tags represented, no sensitive content, exactly one primary category per case, and each primary category included in that case's expected response-category set. Malformed log content is permitted as a tag, but invalid application submissions are exercised by separate safety tests. If `primary_category` is `UNKNOWN`, `expected_categories` includes `UNKNOWN` and partial credit for returning `UNKNOWN` is disabled. At the 15-case floor, category coverage consumes at least 12 primary-category assignments; the other three or more cases increase breadth. Tags can overlap, so the floor remains 15.

### EvaluationAttemptResult

Ephemeral or sanitized report content for one independent stochastic generation attempt. There are exactly three attempt records (1, 2, 3) per dataset case in every complete run, including failed invocation slots.

| Attribute | Type | Constraints |
|---|---|---|
| `case_id` | string | References one case from the declared dataset version. |
| `attempt_number` | integer | Exactly 1, 2, or 3 for each case. |
| `model_provenance` | ModelProvenance reference | Captures actual model digest, runtime version, loopback endpoint, temperature, omitted-seed policy, context and output limits; records unavailable values and a failure reason if invocation cannot start. |
| `generation_status` | enum | `generated`, `model_unavailable`, `timeout`, `invalid_output`. Schema, invariant, and safety outcomes are separate fields/gates, not generation statuses. |
| `schema_valid` | boolean | Result of independent JSON Schema validation. |
| `invariant_failures` | reason-code array | Cross-field, evidence grounding, input-boundary, or generation-configuration failures. Safety outcomes are recorded separately. No raw text. |
| `safety_status` | enum | `passed`, `failed`, or `not_applicable`. An independent safety validator inspects every available generated response without relying on schema/invariant results; no-output unavailable/timeout attempts use `not_applicable` and still fail the model gate. |
| `safety_failure_reasons` | reason-code array | Empty unless `safety_status` is `failed`; then contains only codes from version `SAFETY-1`: `SAFETY_EVIDENCE_UNGROUNDED`, `SAFETY_SENSITIVE_DATA_EXPOSURE`, `SAFETY_UNSAFE_ACTION`, `SAFETY_INSTRUCTION_ISOLATION_FAILURE`. Unknown codes are rejected. |
| `rubric_points` | object of five integer values | `category`, `evidence`, `root_cause`, `suggested_actions`, `uncertainty`; each 0–2. |
| `earned_points` | integer | Sum of five rubric dimensions, 0–10. |
| `failure_reasons` | reason-code array | Sanitized identifiers only. If aggregate semantic score is below 80%, every attempt below 10 points has `SEMANTIC_CASE_BELOW_FULL_SCORE` exactly once; a 10-point attempt never receives this code. Independent failures may also be listed. |
| `sanitized_response_artifact` | relative path | Immutable sanitized response or safe failure artifact under the run's `responses/` directory. Every attempt has an artifact, including model-call failures. Never an absolute path or raw-input path. |
| `response_sha256` | lowercase hexadecimal string | Digest of exact sanitized artifact bytes. |

### EvaluationRun

A repeatable whole-dataset run with retained provenance and sanitized evidence.

| Attribute | Type | Constraints |
|---|---|---|
| `evaluation_status` | enum | `FAIL`, `PASS`, or `PENDING_REPAIR`; records automated evaluation only. `PASS` does not mean resource compliance, constitution compatibility, human approval, or system acceptance. |
| `system_acceptance_status` | enum | `BLOCKED`, `PENDING_RESOURCE_VERIFICATION`, `PENDING_GOVERNANCE_DECISION`, `PENDING_HUMAN_REVIEW`, `ACCEPTED`, `REJECTED`; independent of automated evaluation status. |
| `resource_status` | enum | `NOT_MEASURED`, `PASS`, `FAIL`, `REMEDIATION_REQUIRED`; `PASS` requires the fixed benchmark at or below 2 GiB. |
| `constitution_compatibility` | enum | `PENDING_OWNER_REVIEW`, `COMPATIBLE`, or `REQUIRES_REDESIGN_OR_FORMAL_AMENDMENT`; only a documented project-owner determination after measurement can set `COMPATIBLE`. |
| `resource_evidence_reference` | relative path or absent | Sanitized reference to the fixed workload and measured resource evidence; required before system acceptance. |
| `constitution_compatibility_evidence_reference` | relative path or absent | Reference to the documented project-owner compatibility determination; required before system acceptance. |
| `dataset_version`, `rubric_version`, `application_version` | strings | Required provenance identifiers. |
| `model_provenance` | ModelProvenance | Actual local model/runtime versions, digest, and loopback endpoint used by the run. |
| `generation_config` | object | Effective nonzero temperature, seed omitted, context limit, and maximum output limit. |
| `dataset_case_count` | integer | Number of parsed case entries in the selected dataset; zero if the dataset cannot be parsed. |
| `case_count` | integer | Number of unique dataset cases; at least 15 for possible pass. Zero for dataset-preflight failure. |
| `attempt_count` | integer | Exactly `3 × case_count` when preflight succeeds; zero when preflight fails. |
| `threshold_percent` | number | At least 80; declared before run; never lowered to obtain a pass. |
| `semantic_score_percent` | number | `100 × total_attempt_points / (10 × attempt_count)`, equivalently `100 × total_attempt_points / (30 × case_count)`, bounded 0–100 when preflight succeeds; zero without division if there are no attempts. |
| `schema_failure_count`, `invariant_failure_count`, `safety_failure_count`, `model_failure_count` | integers | Non-negative counts reported independently over the three attempts per case; safety count equals the number of attempts with `safety_status: failed`. |
| `safety_catalog_version` | constant string | Exactly `SAFETY-1`; catalog changes require a new version, corresponding tests, and reevaluation. |
| `attempt_results` | flat array | Exactly three records per dataset case, grouped by `case_id`; no separate case-summary object is required. Each record exposes generation, schema, invariant, safety, and rubric outcomes and preserves that attempt's sanitized artifact. |
| Safety reconciliation | invariant | A failed attempt has one or more `SAFETY-1` codes and matching top-level failures with `gate_name: safety`, `case_id`, `attempt_number`, and the same reason code; unknown codes fail validation. `safety_failure_count` equals failed attempt statuses. `not_applicable` is allowed only for unavailable/timeout attempts with no output and is not a safety pass. |
| `failed_case_ids` | string array | IDs from this run only. |
| `human_review` | object or absent until review | Decision, fixed `human_reviewer` role, and one fixed reason code; no personal identity or free-form rationale. No review means not accepted. |
| `repair_reference` | optional string | Link/identifier for a repair; previous report remains immutable. |

`SAFETY-1` meanings and independent validation checks are normative in the [specification catalog](spec.md#evaluation-harness). The report schema enumerates exactly those codes. Unknown codes MUST fail validation; changes require a catalog version, tests, and reevaluation.

The fixed SC-009 resource workload is defined in [spec.md](spec.md#evaluation-harness): three exact dataset fixture IDs, three cold-start sessions and a warm session with specified repetitions/configuration, one-second sampling of unique PIDs in both process trees, and ≤2 GiB maximum combined working set. Record workload and measured results in `docs/evidence/model-resource-acceptance.md`; no result is assumed here.

Automated evaluation `PASS` requires dataset preflight success, `dataset_case_count == case_count`, at least 15 cases, exactly three attempt results per case, all category/tag coverage constraints, zero schema/invariant/safety/model-call failures, and semantic score ≥80%. This pass does not imply overall system acceptance. Overall `ACCEPTED` requires automated `PASS`, `resource_status: PASS` under the exact ≤2 GiB benchmark, documented `constitution_compatibility: COMPATIBLE` determination by the project owner, a resource evidence reference, and human approval. A measured cap pass alone does not establish that the architecture is not resource-intensive. If compatibility is unresolved or negative, acceptance remains blocked pending redesign or a separately approved constitution amendment. Each attempt's earned points equal the sum of its five rubric dimensions; aggregate equals total attempt points divided by `10 × attempt_count` (`30 × case_count`). If aggregate semantic score is below 80%, each attempt with fewer than 10 points has exactly one `SEMANTIC_CASE_BELOW_FULL_SCORE` reason, 10-point attempts have none, and the run has exactly one `DATASET` threshold failure `SEMANTIC_SCORE_BELOW_THRESHOLD`. If aggregate is at least 80%, partial attempt scores alone do not create semantic failures, though independent hard-gate reasons still apply. `failed_case_ids` equals the unique non-sentinel case IDs represented in failure records; each non-sentinel failure refers to an attempt result. A dataset-preflight failure has `case_count == 0`, `attempt_count == 0`, no attempt results, score 0, and a `DATASET` failure record. Repaired candidates create a new run; previous run evidence is never overwritten.

For an aggregate semantic score below 80%, every attempt result with `earned_points < 10` has exactly one failure entry with `gate_name: "semantic"`, `reason_code: "SEMANTIC_CASE_BELOW_FULL_SCORE"`, its `case_id`, and its `attempt_number`; a 10-point attempt has none. The run also has exactly one threshold entry with `case_id: "DATASET"`, `gate_name: "threshold"`, and `reason_code: "SEMANTIC_SCORE_BELOW_THRESHOLD"`. `failed_case_ids` is the unique set of non-sentinel case IDs in all failure entries.

### HumanReviewDecision

| Attribute | Type | Constraints |
|---|---|---|
| `decision` | enum | `APPROVED`, `REJECTED`, or `REQUEST_REPAIR`; approval is permitted only after every automated gate passes. |
| `reviewer_role` | constant string | Exactly `human_reviewer`; not an individual identity. |
| `decision_reason_code` | enum | `REVIEW_COMPLETE_ACCEPT`, `REVIEW_REJECT_QUALITY`, `REVIEW_REJECT_SAFETY`, `REVIEW_REJECT_EVIDENCE`, `REVIEW_REQUEST_REPAIR`, or `REVIEW_OTHER`; code must correspond to the decision. |

The decision is attached to one evaluation run. An approval uses `REVIEW_COMPLETE_ACCEPT`; rejection uses one of the `REVIEW_REJECT_*` codes or `REVIEW_OTHER`; repair request uses `REVIEW_REQUEST_REPAIR`. No reviewer name, email, username, personal handle, or free-form rationale is recorded. A repair request references a new run; it never replaces the previous run or its artifacts.

## Rubric matching and aggregation

- Normalize expected and actual property strings by Unicode normalization, case-folding, and collapsing whitespace; do not strip punctuation unless the case predicate explicitly says so.
- A required marker is met if its normalized literal text occurs in the normalized designated response field(s). A forbidden marker present in those fields caps that dimension at zero.
- Category: 2 for a response category in `expected_categories`; 1 for `UNKNOWN` only when `unknown_partial_credit` is true and `UNKNOWN` is not acceptable; otherwise 0. Dataset preflight rejects a `primary_category` absent from `expected_categories` and disables this partial credit when primary category is `UNKNOWN`.
- Evidence: when `expected_evidence_empty` is true, award 2 only for an empty evidence array, otherwise 0. When false, award 2 when all required markers are present, no forbidden marker appears, and all excerpts are relevant, grounded, and sanitized; award 1 when at least one required marker is present with those same safety/grounding conditions; award 0 otherwise, including an empty array.
- Root cause: at least one required cause property is mandatory. Award 2 when all required properties appear and no forbidden/unsupported property appears; award 1 when at least one required property appears and no forbidden/unsupported property appears; award 0 otherwise.
- Suggested actions: when `expected_actions_empty` is true, award 2 only for an empty actions array, otherwise 0. When false, award 2 when all required properties appear, no forbidden property appears, and all actions are relevant and safe; award 1 when at least one required property appears with those same relevance/safety conditions; award 0 otherwise, including an empty array or unsafe action.
- Uncertainty: each case declares exactly one expected confidence value. Award 2 when expected status, confidence value, and missing-information flag all match; award 1 only when safe partial credit is enabled, at least one matches, and the output is cautious (`confidence < 0.70` and missing-info true); otherwise 0.
- Each attempt has 10 possible points across five dimensions. Aggregate denominator is exactly `30 × case_count`, equal to `10 × attempt_count`. A model-call failure, unparseable response, or schema-invalid response receives zero semantic points for that attempt while retaining its 10-point denominator. Hard model/schema/invariant/safety failures remain independent run-fail gates and cannot be offset by points. On dataset-preflight failure, no attempt is submitted, score is 0, and no division is performed. Compute the threshold comparison from the unrounded ratio; report the percentage rounded to six decimal places.

## Relationships

- One `LogSubmission` yields one transient `ExplanationResponse`.
- One `EvaluationRun` references one dataset version, rubric version, application version, model/runtime provenance and generation configuration, and exactly three `EvaluationAttemptResult` records per case.
- A `HumanReviewDecision` belongs to one run. A repair creates a new run linked by `repair_reference`; it does not mutate prior run evidence.
